## Pixel 10 launch repair

v0.1 physically crashed immediately on a Pixel 10. v0.2 added an on-screen launch guard, which exposed the actual exception rather than silently disappearing:

`NullPointerException` while Android attempted `DecorView.getWindowInsetsController()` on a null object.

Root cause was the inherited v70 developer activity calling `applyImmersiveUi()` before `setContentView(root)`. On the Pixel 10 / Android 16 launch path the DecorView was not attached yet.

v0.3/v0.4 carry the actual lifecycle repair:

1. build and attach the root content first;
2. render the menu;
3. post immersive setup through the attached root;
4. use `getWindow().getDecorView().getWindowInsetsController()` with a null guard;
5. retain legacy Back handling for the test activity with `android:enableOnBackInvokedCallback="false"`.

RED workflow `34385250721` failed the new Pixel lifecycle contract before the fix. The repaired source passed the contract and v0.4 exact-head build.
