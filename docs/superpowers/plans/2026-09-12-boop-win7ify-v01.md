# BOOP Win7ify v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a BOOP-themed, reversible Windows 11-to-Windows-7-feel utility and a GitHub Actions-built self-contained x64 EXE.

**Architecture:** A pure core library owns tweak definitions, typed registry snapshots, backup/restore, and apply logic behind an `IRegistryStore`. A WinForms front end owns only presentation and Explorer restart. A dependency-free console harness exercises core behavior without touching the CI runner registry.

**Tech Stack:** C# 14 / .NET 10 LTS, WinForms, `Microsoft.Win32.Registry`, `System.Text.Json`, GitHub Actions on `windows-latest`.

**Spec:** `docs/superpowers/specs/2026-09-12-boop-win7ify-v01-design.md`

## Global Constraints

- Branch: `boop-win7ify-v01`, based on current `main`.
- App files live under `win7ify/`; Android app lineages remain untouched.
- v0.1 registry changes are HKCU-only and require no elevation.
- Backup original registry state before first touch and preserve that baseline across repeated Apply operations.
- Delete the backup only after complete successful Restore.
- Never patch protected Windows binaries or silently install third-party shell software.
- Reuse the exact approved BOOP eyes binary unchanged.
- GitHub verifies code/build/artifact integrity; visual/physical Windows behavior is not CI acceptance.
