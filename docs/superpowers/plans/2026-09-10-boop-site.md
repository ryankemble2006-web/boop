# BOOP Static Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and package a dependency-free BOOP public website whose ZIP can be extracted directly into a shared-hosting web root.

**Architecture:** Keep the public site under `site/` on the isolated `boop-site` branch. HTML contains all essential content, CSS owns the visual system, JavaScript adds only optional eye/nav/reveal behavior, and exact protected BOOP asset blobs are reused without modification. A Python contract test verifies deployability, copy boundaries, hashes and the final ZIP layout.

**Tech Stack:** HTML5, CSS3, vanilla JavaScript, Python 3 standard library, Apache `.htaccess`.

**Spec:** `docs/superpowers/specs/2026-09-10-boop-site-design.md`

## Global Constraints

- Do not modify canonical Android/Launcher/Shield app source, package IDs, signer, permissions or protected source assets.
- Eye asset SHA-256 must be `ffbd67af22c2f11b4a109bd83e8c5197c266a777df2fbc97ce1ab5163e9fed22`.
- Locked yellow-hand asset SHA-256 must be `26fe95570ac995e08b693107db4324f038cebe9e4fe76b9174ec41d7556fe2f1`.
- No framework, external font, analytics, cookies, backend, account system, CDN runtime dependency or automatic APK/latest-release link.
- Main content must remain useful with JavaScript disabled.
- Future hardware is visibly labelled `Concept`.
- Automated checks verify contracts only, never visual acceptance.
- Final ZIP contains `index.html` at archive root and no enclosing project folder.
